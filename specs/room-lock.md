# 정산 방 잠금/열림 (편집 권한 개방)

상태: 완료

## 목적 (한 줄)
마스터가 참석하지 못하는 날에도 다른 참가자들이 정산 기록을 입력할 수 있도록, 방 단위로 편집 권한을 열고 잠글 수 있게 한다.

## 사용자 시나리오
1. 마스터가 참석하지 못하는 날의 방을 미리 생성한다. 방은 기본적으로 **잠김** 상태다.
2. 마스터가 해당 방에 들어가 `열어주기` 버튼을 누른다. 상태가 **열림**으로 바뀐다.
3. 참가자가 그 방에 들어가 정산 내용을 입력하고 저장한다. (로그인 절차 없이 익명 인증이 자동으로 처리됨)
4. 게임이 끝나면 마스터가 다시 들어가 `잠그기` 버튼을 누른다. 확인 창이 뜨고, 확인하면 **잠김**으로 돌아간다.
5. 이후 그 방은 마스터 외에는 수정할 수 없다.
6. 마스터가 참석하는 평소 날에는 방을 잠근 채로 마스터 본인이 입력한다. (잠김 상태여도 마스터는 항상 수정 가능)

## 요구사항

### R1. 데이터 모델
- 대상: `rooms/{날짜}` **단일 문서 구조**. 서브컬렉션 없음.
- 기존 문서에 필드 2개를 추가한다.

| 필드 | 타입 | 기본값 | 설명 |
|---|---|---|---|
| `locked` | boolean | `true` | `true` = 잠김, `false` = 열림 |
| `lastEditedAt` | timestamp | - | 마지막 수정 시각. 저장 시 갱신 |

- **신규 방 생성 시 `locked`는 반드시 `true`로 생성한다.**
- **기존 문서에는 `locked` 필드가 없다.** 필드가 없으면 **잠김으로 간주**한다.
  - 클라이언트: `const locked = data.locked !== false;`
  - 보안 규칙: `resource.data.get('locked', true)`
  - 별도 마이그레이션 스크립트는 실행하지 않는다. 마스터가 해당 방을 수정하면 자연스럽게 필드가 채워진다.
- `lastEditedBy`(편집자 식별) 필드는 **만들지 않는다.** 익명 uid는 기기/캐시에 따라 바뀌어 사람을 식별할 수 없으므로 의미가 없다.

### R2. 인증 (익명 인증 도입)
- Firebase Console에서 **Anonymous Authentication을 활성화**한다.
- `index.html` 로드 시, 로그인 세션이 없을 때만 익명 로그인을 시도한다.

````js
// ⚠️ 반드시 조건부로 감쌀 것.
// 무조건 호출하면 마스터의 이메일 로그인 세션이 익명 세션으로 덮어써진다.
if (!auth.currentUser) {
  auth.signInAnonymously().catch(e => console.warn('익명 인증 실패', e));
}
````

- 익명 인증이 실패해도 **조회는 정상 동작해야 한다.** (읽기는 공개 유지)
- 익명 사용자는 마스터로 취급하지 않는다. 기존 `HOST_EMAIL` 비교 로직(`recomputeRole()`)은 그대로 두되, 익명 계정에는 `email` 값이 없으므로 자연스럽게 false가 되는지 확인한다.

### R3. 권한 규칙 (Firestore 보안 규칙)

권한 매트릭스:

| 동작 | 마스터 | 익명 인증 사용자 | 미인증 |
|---|---|---|---|
| read | ✅ | ✅ | ✅ |
| create | ✅ | ❌ | ❌ |
| delete | ✅ | ❌ | ❌ |
| update (열림 방) | ✅ | ✅ | ❌ |
| update (잠김 방) | ✅ | ❌ | ❌ |
| `locked` 필드 변경 | ✅ | ❌ | ❌ |

규칙 초안 (실제 배포 전 Firebase Console의 Rules Playground로 검증할 것):

````js
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    function isMaster() {
      return request.auth != null
          && request.auth.token.email == 'iamrlgns@gmail.com';
    }

    // 필드가 없는 기존 문서는 잠김으로 간주
    function isOpen() {
      return resource.data.get('locked', true) == false;
    }

    // 마스터가 아니면 locked 값을 바꿀 수 없다
    function lockUnchanged() {
      return request.resource.data.get('locked', true)
          == resource.data.get('locked', true);
    }

    match /rooms/{roomId} {
      allow read: if true;
      allow create, delete: if isMaster();
      allow update: if isMaster()
                    || (request.auth != null && isOpen() && lockUnchanged());
    }
  }
}
````

- `lockUnchanged()`가 이 스펙의 **가장 중요한 방어선**이다. 이게 없으면 일반 사용자가 정산 내용을 저장하면서 `locked: false`를 함께 실어 보내 잠긴 방을 열어버릴 수 있다.
- 클라이언트 코드에서 막는 것은 UX일 뿐이며, 실제 권한 보장은 이 규칙이 담당한다.

### R4. 상태 배지 UI
- 방 화면 상단, **날짜 칩 우측**에 배지 1개를 표시한다.
- 상태는 2가지만 존재한다.

| 상태 | 라벨 | 색 | 아이콘 |
|---|---|---|---|
| `locked: true` | `잠김` | 무채색 (`--text-dim` 계열, 조용하게) | 닫힌 자물쇠 |
| `locked: false` | `열림` | 초록 계열 (`--felt` 계열, 눈에 띄게) | 열린 자물쇠 |

- 색 대비 의도: **잠김이 평상시 상태**이므로 조용해야 하고, **열림은 비정상/일시적 상태**이므로 튀어야 한다. 열어두고 잊은 방을 시각적으로 잡아내기 위함이다.
- 배지는 마스터/일반 사용자 모두에게 동일하게 보인다.

### R5. 마스터 토글 버튼
- 위치: **기존 삭제 버튼 좌측**. 마스터에게만 노출한다.
- 라벨은 현재 상태에 따라 바뀐다.

| 현재 상태 | 버튼 라벨 | 동작 | 확인창 |
|---|---|---|---|
| 잠김 | `열어주기` | `locked = false` | 없음 |
| 열림 | `잠그기` | `locked = true` | **있음** |

- `잠그기` 확인 문구: `이 방을 잠글까요? 다른 사람은 더 이상 수정할 수 없어요.`
- `열어주기`는 되돌리기 쉬우므로 확인창을 띄우지 않는다.
- **삭제 버튼과 시각적으로 명확히 구분한다.** 삭제는 위험(빨강) 계열, 잠금 토글은 중립 계열로 처리해 오탭을 방지한다.
- 토글은 `locked` 필드만 갱신하는 부분 업데이트(`update`)로 수행한다. 문서 전체를 덮어쓰지 않는다.

### R6. 잠김 상태의 편집 UI 처리
- 잠긴 방을 마스터가 아닌 사용자가 열면, 편집 관련 UI(입력 필드, 바이인 스테퍼, 참가자 추가/삭제, 저장 버튼 등)를 **숨기지 말고 비활성화(disabled)** 한다.
  - 이유: UI가 사라지면 고장으로 오인하지만, 회색으로 남아 있으면 "잠겨서 못 쓴다"로 즉시 읽힌다.
- 기존 view-only 처리 로직(`applyPermissionUI()`)이 있다면 재사용한다. 새로운 판정 조건은 다음과 같다.

````js
// 기존: isHost 만으로 판정
// 변경: 마스터이거나, 방이 열려 있으면 편집 가능
const canEdit = isHost || (state.locked === false);
````

- 잠김 상태에서 비마스터가 저장을 시도할 경우(UI를 우회한 경우 포함), Firestore 권한 오류를 잡아 `이 방은 잠겨 있어요. 마스터에게 열어달라고 요청해주세요.` 를 안내한다.

### R7. 리스트 화면 배지 노출
- **결정: 표시한다** (권장안 채택, 구현 완료). 게임 기록 리스트(`?lobby`)의 각 항목에도 R4와 동일한 배지를 노출한다.

## 완료 조건 (Claude Code가 스스로 검증할 기준)

### C1. 기본값
- 마스터가 새 방을 생성하면 문서에 `locked: true`가 저장되고, 배지가 `잠김`으로 표시될 것.

### C2. 기존 문서 호환
- `locked` 필드가 없는 기존 방을 열었을 때 `잠김`으로 표시되고, 비마스터가 수정할 수 없을 것.
- 콘솔에 `undefined` 관련 에러가 발생하지 않을 것.

### C3. 마스터 세션 보존 (⚠️ 회귀 위험 높음)
- 마스터 이메일로 로그인한 상태에서 페이지를 새로고침해도 **마스터 권한이 유지될 것.**
- 즉 익명 로그인이 마스터 세션을 덮어쓰지 않을 것.

### C4. 토글 동작
- 마스터 화면에서 `열어주기` → 배지가 `열림`으로 즉시 바뀌고 Firestore에 `locked: false`가 반영될 것.
- `잠그기` 클릭 시 확인창이 뜨고, 취소하면 상태가 바뀌지 않을 것.
- 비마스터 화면에는 토글 버튼이 아예 렌더링되지 않을 것.

### C5. 권한 검증 — 열린 방
- 로그아웃(익명) 상태에서 열린 방의 정산 내용을 수정·저장했을 때 정상 반영될 것.

### C6. 권한 검증 — 잠긴 방
- 로그아웃(익명) 상태에서 잠긴 방의 편집 UI가 비활성화되어 있을 것.
- 브라우저 콘솔에서 직접 `update`를 시도하면 **Firestore 규칙 단에서 거부**될 것. (클라이언트 우회 차단 확인)

### C7. locked 필드 변조 차단 (최우선 검증 항목)
- 브라우저 콘솔에서 익명 세션으로 **열린 방**에 대해 `locked: true`(또는 정산 데이터와 함께 `locked` 값 변경)를 포함한 update를 시도했을 때 **거부**될 것.
- 잠긴 방에 대해 `locked: false`로 바꾸는 시도도 **거부**될 것.

### C8. 생성/삭제 차단
- 익명 세션에서 새 문서 `create`와 기존 문서 `delete`가 모두 규칙에서 거부될 것.

### C9. 읽기 유지
- 인증이 전혀 없는 상태(익명 로그인 실패 상황 포함)에서도 방 목록과 방 내용 **조회는 정상 동작**할 것.

## 제외 범위 (이번에 안 하는 것)
- **자동 마감(`openUntil` 만료 시각)** — 리스트의 `열림` 배지가 같은 역할을 하므로 불필요. 실사용 후 방치 사례가 반복되면 재검토
- **편집자 이름 표시 / 편집 이력 목록** — 익명 uid로는 사람을 식별할 수 없고, 이름 입력 UI 추가는 범위 밖
- **방 생성 개방(비마스터의 방 생성)** — 무한 생성 스팸 리스크. 마스터가 사전에 방을 만들어두는 운용으로 처리. v2에서 재검토
- **동시 편집 충돌 처리** — 마지막 저장이 이기는 방식(last-write-wins) 유지. 락/머지 로직 없음
- **계정별 권한 시스템(마스터가 특정 계정에 권한 부여)** — 별도 스펙(`auth-user-roles.md`)
- **참여자 본인 게임만 필터링** — 별도 스펙
- **잠금 상태 변경 알림/푸시** — 하지 않음

## 참고 (관련 파일, 기존 코드, 디자인 톤)
- 관련 파일: `index.html` 단일 파일
  - 권한 판정: `recomputeRole()`, `applyPermissionUI()`, `isHost`, `HOST_EMAIL`
  - 방 진입: `enterRoom()`, 리스트 렌더링부
  - 날짜 칩 영역: `#game-date` 주변 (`openDateEdit()`, `onDateInputChange()` 참고)
- Firestore 보안 규칙은 **Firebase Console에서 직접 배포**해야 한다. 저장소 코드 변경만으로는 반영되지 않는다.
  - 규칙 초안을 `firestore.rules` 파일로 저장소에 함께 커밋해 이력을 남길 것 (배포는 수동)
- 톤: 기존 라이트 테마 및 한국어 UI 라벨 유지. `--gold`, `--felt`, `--text-dim` 등 기존 CSS 변수 사용
- 용어 통일: 상태는 `잠김`/`열림`, 버튼은 `열어주기`/`잠그기`. "마감", "수정 허용", "보기 전용" 등 다른 표현을 혼용하지 말 것
