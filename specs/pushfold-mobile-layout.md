# Push/Fold 차트 모바일 레이아웃 개선
상태: 확정 (2026-11-10)

## 목적 (한 줄)
폰에서 설정(인원·포지션·칩 등)을 바꿨을 때 스크롤하지 않고도 차트 결과가 바로 보이게 한다.

## 사용자 시나리오
1. 사용자가 폰으로 Push/Fold 차트를 열면 → 설정 영역과 함께 결과(푸시 비율 + 차트 일부 이상)가 첫 화면에 보인다
2. 사용자가 보유 칩을 10BB → 8BB로 바꾸면 → 위아래로 스크롤하지 않고 결과 변화를 바로 확인한다
3. 사용자가 인원·포지션을 바꾸면 → 마찬가지로 결과가 화면 안에 보인다

## 요구사항
- 현재: 375px에서 설정 영역(행동/인원 9개/포지션 최대 8개/칩 15개/앤티)이 첫 화면 거의 전체(약 860px)를 차지해 결과가 화면 밖에 있음 (2026-11-10 실측)
- 아래 두 방안 중 하나를 확정 시 선택한다 (결정 필요 D1)

### 방안 A — 설정 압축
- 인원(2~10명), 보유 칩(1~15BB) 버튼을 각각 **한 줄 가로 스크롤**로 바꾼다
  - 선택된 값이 항상 보이도록 선택 시 해당 버튼을 가운데로 스크롤
- 포지션은 현재처럼 줄바꿈을 허용 (최대 8개)
- 목표: 375×812에서 결과 요약(42.0%)과 차트 상단 3줄 이상이 첫 화면에 보임

### 방안 B — 결과 고정
- 결과 요약 줄(푸시 비율 + 조건 요약)을 화면 상단에 sticky로 고정
- 차트는 기존 위치 유지, 설정 변경 시 요약 수치만 즉시 보임
- 차트 자체를 보려면 여전히 스크롤 필요 (A보다 덜 근본적)

## 결정 사항 (2026-11-10 확정 — 사용자가 제안안 일괄 채택)
- D1. **방안 A(설정 압축)** 로 구현한다. 방안 B는 하지 않는다
- D2. 보유 칩은 **버튼 유지** (슬라이더 아님)
- 가로 스크롤 압축은 모바일(≤600px)에만 적용하고, 데스크톱은 기존 줄바꿈 배치 유지

## 완료 조건 (무인 실행 시 스스로 검증할 기준)
- [ ] 375×812 뷰포트에서 첫 화면(scrollY=0)에 결과 요약 수치 요소가 `getBoundingClientRect().bottom ≤ 812`로 보이는지 확인
- [ ] (A 선택 시) 차트 격자 상단 3줄이 첫 화면 안에 보이는지 확인
- [ ] (A 선택 시) 가로 스크롤 줄에서 선택된 버튼이 화면 안에 보이는지 확인 (예: 15BB 선택 후)
- [ ] 페이지 전체 `scrollWidth`가 뷰포트 폭과 같은지 확인 (가로 스크롤은 해당 줄 안에서만)
- [ ] 모든 설정 조합에서 차트 결과(푸시 콤보 수 등)가 변경 전과 동일한지 몇 가지 조합으로 확인 (로직 변경 없음)
- [ ] 1280px에서 기존 레이아웃이 유지되는지 확인
