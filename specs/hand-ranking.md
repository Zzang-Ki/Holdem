# Hand Ranking (핸드 랭킹)
상태: 확정

## 목적 (한 줄)
169개 스타팅 핸드를 "상위 몇 %"라는 하나의 기준으로 줄 세워, 6단계 등급 색상 격자 한 장으로 세기를 익히고 개별 핸드의 순위·백분위·등급을 확인하는 독립 페이지를 만든다.

## 사용자 시나리오
1. 사용자가 홈에서 "Hand Ranking" 진입점을 탭하면 → `hand-ranking.html`로 이동해 169칸이 6단계 등급 색으로 칠해진 격자가 보인다
2. 사용자가 격자에서 `A5s`를 탭하면 → 하단 정보 영역에 핸드명 / 등급 / 169개 중 순위 / 상위 % / 콤보 수 / 등급 한 줄 코멘트가 표시된다
3. 사용자가 "상위 20%" 칩을 선택하면 → 상위 20%에 해당하는 칸들이 굵은 테두리로 묶여 표시되고, 상단에 `상위 20% · 265콤보 / 1,326`처럼 실제 수치가 뜬다
4. 사용자가 표시 기준을 "백분위 농도"로 바꾸면 → 같은 격자가 등급 6색 대신 단색 농도 그라데이션으로 다시 칠해진다
5. 사용자가 하단 링크를 탭하면 → Push/Fold 차트로 이동한다 (반대 방향도 동일)

## 요구사항

### 페이지 구조
- 신규 단일 파일 `hand-ranking.html`을 만든다. 프레임워크/빌드 도입 없음
- `pushfold-chart.html`과 동일 레벨의 독립 페이지. 헤더 로고/뒤로가기, 카드·칩·격자 CSS 톤을 그대로 재사용한다
- 페이지 타이틀은 `Hand Ranking`(영문 표기 유지), 그 외 모든 UI 라벨·설명은 한국어
- 홈 진입점은 `home-grid-redesign.md`가 아직 초안 상태이므로, 이번에는 `index.html`의 기존 `.home-nav-btn` 방식으로 링크 1개만 추가한다 (그리드 개편 스펙 구현 시 진입점 배열로 이관)

### 순위 데이터 (⚠️ 핵심)
- 핸드 정렬 순서는 **`pushfold-chart.html`의 `ORDER` 배열(중복 제거·누락 보충 후의 169개 최종 배열)을 그대로 사용한다.** 새로운 순위 체계를 만들지 않는다
- 이유: 두 페이지에서 같은 핸드의 순위가 다르게 보이는 혼란을 원천 차단하고, 신규 데이터 생성 리스크를 없앤다
- 구현 방식: `hand-ranking.html` 안에 동일한 배열을 복제하되, 두 파일 모두에 `/* SOURCE OF TRUTH: 핸드 순서 배열 — 두 파일 동일하게 유지 */` 주석 마커를 남긴다
  - 세 번째 페이지가 이 배열을 필요로 하게 되면 그때 `hand-order.js`로 분리한다 (지금은 하지 않음)
- **1대1 승률(equity) 값은 이번 버전에서 다루지 않는다** (제외 범위 참고)

### 백분위 정의
- `순위(rank)` = ORDER 배열 인덱스 + 1 (1~169)
- `상위 %` = **해당 핸드까지의 누적 콤보 수 ÷ 1,326**, 소수 첫째 자리까지 표시
  - 예: AA = 6/1326 → `상위 0.5%`, 마지막 핸드 = 1326/1326 → `상위 100.0%`
- 콤보 수: 페어 6 / 수티드 4 / 오프수트 12
- 핸드 개수(rank/169) 기준이 아니라 **콤보 누적 기준**이다. Push/Fold 차트와 계산 방식을 통일한다

### 등급 (6단계)
| 등급 | 표기 | HEX | 상위 % 경계 | 참고 |
|---|---|---|---|---|
| 신화 | Mythic | `#E53E3E` | ~3% | AA·KK·QQ·JJ·AKs·AKo (6핸드 / 40콤보 / 3.0%) |
| 전설 | Legendary | `#F97316` | 3~8% | TT ~ 77 (누적 108콤보 / 8.1%) |
| 영웅 | Epic | `#A855F7` | 8~15% | A9s ~ A6s (누적 200콤보 / 15.1%) |
| 희귀 | Rare | `#3B82F6` | 15~30% | ~ K9o (누적 398콤보 / 30.0%) |
| 고급 | Uncommon | `#10B981` | 30~50% | 누적 663콤보 |
| 일반 | Common | `#9CA3AF` | 50~100% | 나머지 전부 |

- 경계는 하드코딩하지 않고 `[3, 8, 15, 30, 50, 100]` 형태의 상수 배열 하나로 관리한다 (경계 조정 시 한 줄만 수정)
- 셀 배경 = 등급 색, 글자 = 흰색. **단 `일반(#9CA3AF)` 등급만 흰 글자 대비가 부족하므로 글자색을 `--ink` 계열 진한 색으로 처리한다**
- 등급명은 한국어 우선 표기, 괄호로 영문 병기 (예: `영웅 (Epic)`)

### 등급별 한 줄 코멘트
- 신화 (Mythic) — `이 핸드에 내 칩 모두하고 내 손모가지를 건다`
- 전설 (Legendary) — `묻고 더블로 가!`
- 영웅 (Epic) — `끝까지 가면 내가 다 이겨`
- 희귀 (Rare) — `"이 정도면 나쁘지 않은데?" 하고 들어갔다가 칩 녹는 핸드`
- 고급 (Uncommon) — `쌀 때 플랍까지만 보는 핸드`
- 일반 (Common) — `묻지도 따지지도 말고 Fold`

### 격자 / 인터랙션
- 13×13, 좌상단 AA → 우하단 22. 대각선 위쪽 수티드 / 아래쪽 오프수트 (Push/Fold 차트와 동일 배치)
- 표시 기준 토글 2가지: `등급 6색`(기본) / `백분위 농도`(단색 농도 그라데이션, 기준색 `--teal` #14919B)
- 상위 % 하이라이트 칩: `5% / 10% / 15% / 20% / 30% / 끄기`
  - **색을 덮어쓰지 않고 굵은 테두리(윤곽선)로 표시한다.** 등급 색과 동시에 읽히도록 겹쳐서 그린다
  - 상단에 `상위 20% · 265콤보 / 1,326` 형태로 실제 수치 표시
- 셀에는 **핸드명만 표기한다.** 상위 % 숫자는 넣지 않는다 (390px 가독성 우선)
- 핸드 탭 → 하단 정보 영역 표시, 같은 핸드 재탭 → 해제 (Push/Fold 차트 `info` 영역 동작과 동일)
- 다중 선택·드래그 편집은 하지 않는다 (단일 선택만)
- 범례(legend)에 6등급 색상 + 각 등급의 상위 % 구간을 함께 표기한다

### 문구 / 성격 구분
- 하단 주의문에 Push/Fold 차트와의 차이를 명시한다
  - 예시 톤: `이 표는 핸드 자체의 세기 순서예요. 실제로 올인할지 말지는 스택·인원·포지션에 따라 달라지니 Push/Fold 차트를 함께 보세요.`
- 순위 기준이 Push/Fold 차트와 **동일한 배열**임을 명기한다 (두 페이지 순위가 항상 일치하는 것이 강점이므로 문구로 살린다)
- 등급 코멘트는 의도적으로 가벼운 농담 톤이다. 임의로 정중하게 다듬거나 문장을 늘리지 말고 **적힌 그대로** 사용한다

### 페이지 간 이동
- Push/Fold 차트 ↔ Hand Ranking 이동은 **각 페이지 하단 텍스트 링크**로 처리한다
- 상단 탭 구조로 묶지 않는다 (두 페이지 헤더 구조 변경 없음)

## 완료 조건 (Claude Code가 스스로 검증할 기준)
- [ ] 격자에 정확히 169칸이 렌더되고 누락·중복이 없다 (`new Set(핸드명).size === 169`)
- [ ] 콤보 수 합계가 정확히 1,326이다
- [ ] `순위`가 1~169 중복 없이 전부 존재한다
- [ ] `hand-ranking.html`의 순서 배열과 `pushfold-chart.html`의 최종 `ORDER` 배열이 **문자 단위로 완전히 동일하다** (양쪽 배열을 뽑아 스크립트로 비교 검증)
- [ ] 등급 분포가 스펙 표와 일치한다: 신화 6핸드(40콤보, 3.0%) / 전설 누적 108콤보(8.1%) / 영웅 누적 200콤보(15.1%) / 희귀 누적 398콤보(30.0%)
- [ ] `AA`의 상위 %가 `0.5%`, 마지막 핸드의 상위 %가 `100.0%`로 표시된다
- [ ] 경계 상수 배열의 값 하나를 바꿨을 때(예: 15 → 18), 코드 다른 곳 수정 없이 색칠과 범례가 함께 갱신된다
- [ ] "상위 20%" 선택 시 테두리가 그려진 칸들의 콤보 합이 1,326의 20%에 근사(±1핸드 이내)하고, 화면 표시 수치와 실제 테두리 칸이 일치한다
- [ ] 하이라이트가 켜진 상태에서 표시 기준을 `등급 6색`↔`백분위 농도`로 전환해도 하이라이트가 유지되고, 등급 색과 테두리가 동시에 식별된다
- [ ] 임의 핸드 3개(`AA` / `A5s` / `72o`)를 탭했을 때 핸드명·등급·순위·상위 %·콤보·코멘트 6개 항목이 모두 채워져 표시된다
- [ ] 등급 코멘트 6개가 스펙 문구와 글자 단위로 일치한다 (임의 수정 없음)
- [ ] `일반(Common)` 등급 셀의 글자가 배경 대비 읽히는지 확인한다 (대비 4.5:1 이상)
- [ ] 모바일 390px 뷰포트에서 격자가 가로 스크롤 없이 정사각형 비율을 유지하고 셀 글자가 잘리지 않는다
- [ ] `index.html` 홈에서 Hand Ranking 진입점 클릭 시 정상 이동한다
- [ ] `pushfold-chart.html`과 상호 이동 링크가 양방향으로 동작한다
- [ ] 외부 네트워크 요청(웹폰트 제외)이 없고, 오프라인에서도 정상 표시된다

## 제외 범위 (이번에 안 하는 것)
- **1대1 랜덤 핸드 상대 승률(equity) 표시** — 백분위 순서와 승률 순서가 어긋나(예: 22 vs AJo) 초보에게 혼란을 주고, 169개 데이터 생성 비용도 발생. 다음 버전에서 "고급 정보 접기" 형태로 재검토
- 레인지 vs 레인지 에퀴티 계산기 (예: JJ+ vs AK) — 성격이 다른 도구, 별도 스펙
- 사용자가 직접 레인지를 칠하고 저장/공유하는 편집 기능 — 다음 버전 후보
- 포지션별 오픈 레인지 프리셋(UTG 오픈, BTN 오픈 등) — Push/Fold 차트와 역할 충돌 정리가 선행 필요
- 핸드별 개별 코멘트 169개 작성 (등급 단위 6개만)
- 플랍 이후(포스트플랍) 지표
- 순서 배열을 `hand-order.js` 등 공용 파일로 분리하는 작업 (3번째 페이지가 필요해질 때)
- 홈 화면 카드 그리드 전환 (`home-grid-redesign.md` 소관)
- 상단 탭 내비게이션 구조 도입
- Firestore 연동 (이 페이지는 읽기 전용 정적 도구, DB 사용 없음)

## 참고 (관련 파일, 기존 코드, 디자인 톤)
- 관련 파일: `pushfold-chart.html` — `handName()`, `combosOf()`, `ORDER` 배열, `.grid`/`.cell` CSS, `info` 영역, 칩 UI `buildChips()`를 최대한 재사용
- 관련 파일: `index.html` (홈 진입점 링크 추가), `specs/home-grid-redesign.md` (그리드 개편 시 진입점 이관 대상)
- 톤: 기본 프레임(배경·카드·칩·헤더)은 Push/Fold 차트 팔레트 유지(`--navy` #1F3A5F, `--cream` #FBF8F1). 격자 안쪽만 6등급 레어리티 색상 사용
- ⚠️ 레어리티 6색은 기존 사이트 팔레트(블루/네이비/틸/그린)와 결이 다른 게임 UI 계열이다. 격자 밖으로 번지지 않게 **격자 내부 + 범례 + 등급 배지에만 한정**해서 쓴다
- 로드맵 백로그의 "Push/Fold 차트 팔레트를 홈과 통일" 항목이 확정되면 프레임 색만 함께 조정하고, 레어리티 6색은 그대로 유지한다
